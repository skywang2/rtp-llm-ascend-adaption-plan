# 算子验证方案（软件包升级场景）

> **场景**：CANN / triton-ascend / torch_npu 等底层包升级后，验证 Ascend NPU 上的算子未被回归破坏。
> **基线环境（golden）**：CANN 9.1.0-beta.3 + triton-ascend 3.2.2 + torch_npu 2.9.0.post3
> **首批升级目标**：CANN 9.2.0 weekly（软链已切到 `cann-9.2.0`）
> **初版测试集**：Qwen3-0.6B（dense，`model_type=qwen_3`）实际命中的 NPU 算子
> **参考**：`docs/Qwen3.5/算子迁移梳理文档/rtp-llm Qwen3.5 算子迁移指导.md`

> **结构说明**：正文（§0–§8）只描述方案逻辑与方法；具体测试用例、代码、算子清单见文末**附录 A/B/C**。

## 0. 范围界定

迁移指导里的大多数算子 **Qwen3-0.6B 用不到**，必须先划清，否则测试集名不副实：

- **MoE 算子**（`sigmoid_gate_scale_add_triton`、`invoke_moe_batched_triton_kernel`、`silu_and_mul`）→ 仅 `qwen3_next` / `qwen_3_moe` 路径
- **线性注意力/GDN 算子**（`causal_conv1d`、`chunk_gated_delta_rule`、`l2norm_fwd`、`fused_gdn_gating`、`load/store_ssm_state_to_block_map`）→ 仅 `qwen3_next` 路径

经源码核实（`model_factory_register.py` → `qwen_3`→`QwenV3` → `model_desc/qwen3.py:Qwen3Model`），Qwen3-0.6B 的 forward **不 import / 不调用**上述任何 Triton 算子，实际命中的 NPU 专属算子只有 3 个（§1）。

测试集分两层：**L1 基础集**（Qwen3-0.6B 实际命中，需其权重，升级后可立即端到端跑）／**L2 完整集**（迁移指导全部算子，合成输入单测、不需权重，见 §7）。**本方案聚焦 L1。**

### 2.1 基线组合

| 组件 | 基线版本 | 来源 |
|---|---|---|
| CANN | **9.1.0-beta.3**（`cann-9.1.0-beta.3`，`Version=9.1.0-beta.3`） | `/usr/local/Ascend/cann-9.1.0-beta.3` |

| triton | 3.2.0 | 随 triton-ascend |
| torch_npu | 2.9.0.post3 | gitcode |
| torch | 2.9.0+cpu | aliyun |

> 升级 = 保持用例集不变，只替换上表某行版本重跑比对。首批目标 = CANN 9.2.0 weekly。

### 2.2 golden 的产生与存储

golden 存为单个 `.pt` 文件，把**输入与输出**一起存盘：

```python
torch.save({"input": inp, "output": out}, "tests/ascend/golden/<op>__<input>__cann9.1.0-beta.3__ta3.2.2.pt")
```

每个 算子×输入规格×基线环境 一份。输入一并存盘是为了升级时用**同一份输入**重跑，消除输入重建差异。

**升级比对**：`torch.load` 取 input → 跑算子 → `torch.allclose(actual, golden["output"], atol=ε, rtol=ε)`，ε 取极小值（bf16 默认 `1e-3`）。

- **通过** = 落在极小容差内 → 算子逻辑未变，仅数值噪声。
- **不过** = 漂移超容差 → **算子逻辑可能变化**，出 `max_abs_diff` 报告人工裁决。
- 量级错误（NaN / 形状错）→ 直接判回归。

确定性算子（scatter、greedy 采样）逐位相等，ε 可更紧（甚至 0）；非确定性算子（FIA）若基线自身重跑就超 ε，说明有数值噪声，按需微调 ε 到刚好不假红（仍保持极小）。

**golden 只追加不覆盖**：基线 .pt 冻结；升级产生新 .pt 与基线对比。

### 2.3 JIT 缓存隔离（防假绿）

triton-ascend 会缓存编译产物，升级后不清缓存会用旧产物导致结果误判（看似通过实际是旧算子）。手动跑测试前强制 `export TRITON_CACHE_DIR=$(mktemp -d)`，跑完即弃。

## 4. 执行方式

> **当前阶段仅手动执行**：环境包（CANN / triton-ascend / torch_npu）更新后，手动跑测试用例验证新环境不影响 rtp 框架运行。暂不接入 CI 自动触发。

**手动验证流程**：

1. 切环境：`source /usr/local/Ascend/ascend-toolkit/set_env.sh` + `conda activate rtp-env`，确认 `pip show triton-ascend` 版本已更新。
2. 清 JIT 缓存：`export TRITON_CACHE_DIR=$(mktemp -d)`（§2.3）。
3. 跑测试：L0（环境冒烟）→ L1（三算子）→ L2（端到端冒烟）。
4. 比对：读基线 `.pt`，每用例 `allclose` 极小容差 + `max_abs_diff`。
5. 判定：按 §5。

**可复用资产**：`bindings/ascend/ops/tests/test_ascend_sampler.py`（算子3）、`cc_test_wrapper.sh`、`.bazelrc` 的 `test:ascend` config（已设 `ASCEND_CUSTOM_OPP_PATH`、`LD_LIBRARY_PATH`）。

## 5. 通过/失败判定矩阵

| 情形 | L0 | 数值判定 | 冒烟 | 判定 |
|---|---|---|---|---|
| 全绿 | ✅ | allclose(极小容差) 过 | ✅ | **升级通过** |
| 漂移超容差 | ✅ | `max_abs_diff > ε` | ✅ | **算子逻辑可能变化**：出 diff 报告，人工裁决，回写 notes |
| 量级错误（NaN/形状） | ✅ | — | ❌ | **真回归**：行为破坏 |
| EZ0026 重现 | ✅ | — | ❌ | **回归**：`cache_mode="Norm"` 补丁失效或算子 ABI 变 |
| triton backend 退化为 cpu | ❌ | — | — | **回归**：triton-ascend 未正确加载 |
| 采样结果变 | ✅ | — | ❌ | **回归**：`aclnnApplyTopKTopPCustom` 变 |
| 全挂 | ❌ | — | — | 环境装错，先修环境再判算子 |

| 风险 | 防护 |
|---|---|
| triton-ascend 历史上未被 `deps/requirements_*ascend*.txt` pin | 本次已补 pin；手动更新后核对版本 |

| 非确定性算子（FIA）单点 .pt + 极小容差可能假红 | 基线自测调 ε 到刚好不假红；必要时基线多跑取一致输出 |

## 附录 A：L1 具体测试用例

### A.1 算子 1 `npu_scatter_pa_kv_cache`
- 契约：`[T, n_kv=8, head_dim=128]` 的 k/v 按 `slot_mapping` 散写到 `kv_cache_base[num_blocks=16, 2, 8, 128]`。
- 输入：T ∈ {1, 7, 32}（decode/小 prefill/中 prefill）；`slot_mapping=[T]` int32。
- 已知坑：Qwen3-0.6B `head_dim=128` 触发 `EZ0026`，必须带 `cache_mode="Norm"`（迁移记录 §10.5）。**升级后头一个要复现的回归点**——补丁失效即红。
- 判定：与基线 .pt golden 极小容差匹配（纯拷贝无算术，确定性，torch `index_copy_` 等价）。

### A.2 算子 2 `npu_fused_infer_attention_score_v2`
- 契约：`input_layout="TND"`、`sparse_mode=3`（causal）、GQA（16 q-head / 8 kv-head）。
- 输入：Prefill `q=[T,16,128]`、`k/v=[T,8,128]`，T ∈ {32, 128}；Decode `q=[1,16,128]`，k/v 取自 kv_cache + `block_table`。
- 判定：无 torch 等价，与基线 .pt golden 极小容差比对（§2.2）。非确定性，基线自测调 ε。

### A.3 算子 3 `aclnnApplyTopKTopPCustom`（采样）
- 复用现有 `bindings/ascend/ops/tests/test_ascend_sampler.py`（7 个固定 greedy case）。
- 判定：greedy 确定性，与基线 .pt golden 精确匹配。

### A.4 端到端冒烟（L1 收口）
拉起 `Qwen3-0.6B` 服务 → `/health` 应 `"ok"` → 发一条 `/v1/chat/completions`（固定 prompt + seed）。比对响应 token 数是否稳定。这条同时覆盖算子 1/2/3 的组合路径，是升级后最快的"能否用"判断。
